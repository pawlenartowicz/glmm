# Warnings and errors

Every warning a fit raises is also stored on the fit: `m.warnings` in Python,
`m$warnings` in R. Every error a call can raise is also listed here. Python
and R show the same text for the same problem; an argument keeps each
language's own spelling (`nagq` / `nAGQ`), and everything else in the message
is identical.

## How a warning looks

Each warning has a tier, a title and a message. It prints as:

```
Tier: Title. Message
```

For example:

```
Severe: Fit failed. The fitting algorithm failed and returned no estimates. Try a simpler random-effects structure or check for nearly collinear predictors.
```

Python and R add their own label in front of it. Python prints the warning class
(`FitFailedWarning: Severe: Fit failed. …`). R prints
`Warning message:` on the line above.

The stored entry has four fields: `tier`, `kind`, `title` and `message`. In
Python it is a `dict`, and `m.warnings` is a list of them. In R, `m$warnings`
is a `data.frame` with one row per warning. Match on `kind` in scripts. The
title and message text can change between versions; `kind` does not.

R raises every kind in the table below as a condition with the classes `fastglmm_<kind>` and `fastglmm_diagnostic`, so `tryCatch()` can select a kind by class, for example `fastglmm_singular`.

## Tiers

| Tier | Meaning |
|---|---|
| Severe | Do not use these results until this is fixed. |
| Caution | The results are usable; read them with this in mind. |
| Note | Something was adjusted; the results are not affected. |

## Warnings

Text in `<angle brackets>` is filled in from the fit.

| Kind | Tier | Title | Message | Description |
|---|---|---|---|---|
| `search_limit` | Severe | Search stopped at its step limit | The search for the variance estimates reached its step limit before it settled. The estimates shown are the best point found; they are often close, but this is not checked. Do not use them until the fit converges. Try a simpler random-effects structure or check for nearly collinear predictors. For a GLMM whose inner steps also ran out of iterations, this sentence comes second: Some of its inner steps ran out of iterations. | LMM and GLMM. The search over the variance parameters (BOBYQA, or BFGS on the gradient routes) used its evaluation budget without meeting its tolerance, and `converged` is false. Everything is reported at the best point found: coefficients, standard errors, variance components and dispersion; fitted values and random-effect modes are NaN. That point is usually close to the optimum, but nothing checks how close. The inner-steps sentence is added when a GLMM's inner penalized IRLS (PIRLS) solve reached its cap of 200 iterations during the search. glmm runs no multi-start; refit with fewer random effects. Rescaling or centering a predictor does not change the search, since glmm standardizes the design internally; nearly collinear predictors can still slow it. Chosen over `fit_failed` when the end point has a finite deviance and every estimated coefficient is finite. Also raised for a GLMM whose gradient search handed over to a BOBYQA search that ended with no result (see `gradient_search_fallback`). An LMM whose search reports convergence with fewer than two finite deviance evaluations (a degenerate surface) is also reported as `search_limit`, since it is not treated as converged either. |
| `fit_failed` | Severe | Fit failed | The fitting algorithm failed and returned no estimates. Try a simpler random-effects structure or check for nearly collinear predictors. For a GLMM whose inner steps ran out of iterations, this sentence comes second: Some of its inner steps ran out of iterations. | LMM and GLMM. The optimizer stopped on a degenerate configuration (a failed step, a non-positive-definite system, or a non-finite deviance at the end point), and `converged` is false. For a GLMM this also covers a search that reports convergence with a failed evaluation (an inner solve that did not finish, so the deviance there is unknown) within its first step size of the end point: the search then stopped at the edge of the region where the deviance fails, not at a checked minimum. Every estimate is NaN, and so are fitted values and random-effect modes. The inner-steps sentence works as for `search_limit`. Also raised for a mixed model with no fixed effects whose end point has no finite deviance. |
| `glm_diverged` | Severe | Fit diverged | The fit did not converge. This usually means a predictor, or a combination of predictors, predicts the outcome perfectly (separation), so some fitted probabilities go to 0 or 1. The coefficients are from the last step; standard errors are not reported. Check the data for separation. | GLM without random effects (IRLS), including the inner fit of a negative binomial GLM, and a GLMM whose fixed-effects-only GLM (its starting fit) found separation; that GLMM stops before its search, with the GLM's last coefficients and no deviance. `converged` is false when one of five checks fires: the deviance stops changing while the last step still moved some linear predictor by more than 0.01; the fit stops while the rounding error of its linear predictor (16 ULPs of the largest linear predictor, or of the largest term the linear predictor sums once a step has been solved on the QR of √W·X) is itself above 0.01, so the last step cannot show whether some linear predictor still moves by more than 0.01, as on a nearly collinear design whose coefficients have grown large and cancel; a step puts some row's linear predictor outside the link's domain and 16 step halvings do not bring it back; X'WX is not positive definite and neither is its rebuild on the QR of √W·X, or a solve fails; or the fit reaches the IRLS iteration cap (`MAX_IRLS_ITERS = 50`, `src/glm.rs`) without converging. The first check is the usual sign of complete or quasi-complete separation. The second is read as separation when the fit ends with a linear predictor more than 30 away from its null-model value. The last three are also read as separation when the fit ends with a linear predictor more than 30 away from its null-model value (the offset on binomial links) and its last step still moving some linear predictor by more than 0.01. A linear predictor past 30 alone stops nothing: a fit with a finite maximum there converges as usual. The coefficients are the last iterate (a fit whose first solve fails has none and raises `design_unsolvable` instead); the standard errors and the deviance are NaN on purpose, because under separation they would be huge and meaningless. The message depends on the family: separation for binomial, all-zero categories for Poisson and negative binomial, and an unsettled fit for Gamma and inverse Gaussian, whose fits skip the linear-predictor check. |
| `glm_diverged` | Severe | Fit diverged | The fit did not converge. This usually means that some category of a predictor, or some combination of predictors, has only zero counts, so some fitted counts go to 0. The coefficients are from the last step; standard errors are not reported. Check for categories whose counts are all zero. | Same as above. |
| `glm_diverged` | Severe | Fit diverged | The fit did not settle on an answer: the fitting steps stopped before converging. The coefficients are from the last step; standard errors are not reported. Check predictors with extreme values; with a link other than log, the log link is usually more stable. | Same as above. |
| `design_unsolvable` | Severe | Predictors could not be separated | The predictors could not be separated numerically, so no estimates were computed. Check for predictors that are copies or near-copies of each other. | Gaussian model without random effects (OLS). The Cholesky factorization of X'X failed, and `converged` is false. Exactly redundant columns are already dropped as aliased before this step, so this means columns that are redundant up to rounding. Every estimate is NaN. Also a GLM without random effects whose first IRLS solve failed (X'WX not positive definite on the Gram or on its rebuild on the QR of √W·X, or a non-finite solve), as when a tiny prior weight sits on the only row that tells two columns apart: no step was taken, so every estimate is NaN. R's `glm` reports such a column as NA instead. |
| `constant_response` | Severe | Response does not vary | Every value of the response is `<value>`, so there is nothing to estimate. Check the response column. | Any model. Raised in place of the model-based non-convergence warnings when `converged` is false and every row of the response has the same value (after lowering: a two-column binomial response is the proportion). A binomial response of all 0 or all 1 is refused before any iteration. On a mixed model the fit also stores the `separated` note (see that row). It takes precedence over the model-based kinds, including `design_unsolvable`. A constant non-zero response can still converge for some families (a constant Poisson or Gamma response, for example), and then nothing is raised; this kind is raised only when the fit did not converge. |
| `too_few_rows` | Severe | Too few rows | The model has `<p>` coefficient(s) to estimate but only `<n>` row(s), so no estimates were computed. Use more rows or fewer predictors. | Raised when `converged` is false and the number of rows is at most the number of estimated coefficients (those not dropped as aliased). OLS and GLM refuse such a design before fitting; a mixed model fails on it. The counts are written out in words the ports build: "1 coefficient", "3 coefficients", "1 row", "2 rows". |
| `no_coefficients` | Severe | Nothing to estimate | The model has no coefficients and no random effects, so there is nothing to estimate. Add an intercept or a predictor. | A model without random effects whose formula leaves no fixed-effect column, either because the formula has none (the formula lowering already refuses `y ~ 0`) or because every column was dropped as aliased. OLS and GLM refuse it before fitting. |
| `no_coefficients` | Severe | Nothing to estimate | The model has no fixed-effect coefficients: every fixed-effect column is all zero. glmm needs at least one fixed effect in a mixed model. Add an intercept or a predictor. | A model with random effects whose fixed-effect columns were all dropped as aliased, which happens only when every one of them is all zero (the alias check never drops the first column that is not). The mixed model is not fitted without fixed effects, so `converged` is false. |
| `separated` | Severe | Separation | None of its own: the fit's `glm_diverged` warning carries the message. | GLM and GLMM with a binomial, Poisson or negative binomial family. The fixed-effects IRLS stopped on separation: the deviance settled while the last step still moved some linear predictor by a large amount, so at least one coefficient runs off to ±∞. `converged` is false. On a GLMM this is the GLM the search starts from, so the search never ran and the random-effect outputs, standard errors and deviance are NaN. A binomial GLMM whose response is all 0 or all 1 carries this note too, with no iteration: the GLM refuses that response, its maximum sits at an infinite intercept, so the search does not run and β is NaN. A GLM with the same response does not carry the note. Both raise `constant_response` instead of `glm_diverged`. The note is stored in `diagnostics["notes"]` / `diagnostics$notes` and raises no warning of its own. |
| `dispersion_at_limit` | Severe | Dispersion at its search limit | The Gamma dispersion fell below `<limit>`, the smallest value the fit searches, so no estimates were computed. The response varies less than about `<pct>`% around the fitted means. | Gamma GLMM with a free dispersion. The search for φ runs on `ln φ` inside `[1e-6, 1e6]`; when φ̂ ends within 1e-6 of an edge on the log scale, that point is not a maximum inside the range, so the fit is refused: `converged` is false, the boundary is `no_optimum`, and every estimate is NaN. Raised in place of `fit_failed`, as the fit's one non-convergence warning. On a weighted fit the range applies to φ divided by a power of two near the geometric mean of the weights, so `<limit>` is the edge times that power of two, on the scale of the dispersion the fit reports. `<pct>` is 100·√ of the range's own edge, about the coefficient of variation of a row with a typical weight. A held dispersion (`dispersion=`) is not searched and never raises it. In Rust it is `Note::DispersionAtLimit { limit, edge }`, `edge` the range's own edge. |
| `dispersion_at_limit` | Severe | Dispersion at its search limit | The Gamma dispersion rose above `<limit>`, the largest value the fit searches, so no estimates were computed. The response is far more spread out around the fitted means than a Gamma model can describe. | Same as above, at the upper edge. |
| `pirls_exhausted` | Caution | Last fitting step did not finish | The final step that computes the reported results ran out of iterations. The estimates and their standard errors may be less accurate than usual. Try simplifying the random effects. | GLMM with the Laplace approximation only. After the outer search converges, the fit runs the inner penalized IRLS (PIRLS) solve once more at the final variance parameters; that solve produces the reported coefficients, random-effect modes, weights, deviance and both kinds of standard errors. This warning means that final solve reached its cap of 200 iterations without meeting its tolerance, so every reported number carries some extra numerical error. Cap-outs on trial points the optimizer later rejected do not affect any reported number; they are kept in the fit's notes and not raised. When the outer search also failed, the cap-out is reported inside `search_limit` or `fit_failed` instead. Inner solves under adaptive quadrature (nagq above 1) are not checked. |
| `nb_shape_unsettled` | Caution | Shape search did not settle | The search for the negative binomial shape parameter stopped at its limit of `<rounds>` rounds before it settled. The coefficients and standard errors are computed at the last value it reached, which may not be the best one. | Negative binomial GLM without random effects. The fit alternates between the coefficients (IRLS at a fixed shape) and the shape θ (maximised with the fitted means held fixed), as `MASS::glm.nb` does, for at most 25 rounds, and stops early once θ changes by less than 1e-6 relative. This warning means all 25 rounds ran. The coefficients and standard errors are refit at the reported θ, so they belong to one model. Mixed negative binomial models search θ together with the variance parameters and report a budget stop as `search_limit` instead. |
| `singular` | Caution | Singular fit | The random effects are too complex for the data: a variance is estimated at or near zero, or a correlation at or near −1 or 1. Consider removing the affected random effect. When the fit knows which components are affected, this follows: Affected: `<term>` in `<group>`, … | Raised when either of two checks fires. (a) The optimizer fixed a diagonal element of a random-effect Cholesky factor at its lower bound (1e-4 on glmm's internal scale). On the first term of a block this puts that term's variance at zero. On a later term it can instead mean the term is perfectly correlated with an earlier one, so its printed standard deviation can look ordinary while its correlation is ±1. (b) After fitting, some random-effect standard deviation is at most 1e-3 times the largest one. Check (b) reads the standard deviations on glmm's internal standardized design, not the printed ones, so the printed standard deviations can have a ratio above 1e-3 while `singular` is true, or below it while it is false. The terms after "Affected" are the ones fixed by (a); when only (b) fires, no term is named. The fixed-effect estimates are still valid; the affected variances and correlations are not reliable. To fix it, drop the affected random slope or grouping factor and refit, or, for a correlation at ±1, use `\|\|` to remove the correlation. Singularity is not assessed on a fit that did not converge: the kernel never sets `singular` there (the post-hoc check and the boundary flags are gated on `converged`), so `singular` reads false on a non-converged fit, and the severe warning raised there already says not to use the estimates anyway. The ports still gate this warning on `converged` themselves as a defensive check, in case a future kernel change ever sets `singular` on a non-converged fit. |
| `ill_conditioned` | Caution | Nearly collinear columns | `<column>` is almost a combination of other columns in the model, so its standard error is large. Its estimate is still correct, but imprecise. The other columns involved are not named. Consider dropping or combining predictors that carry the same information. | Raised for OLS, GLM, LMM and GLMM fits. glmm factors the fixed-effect cross-product (X'X; X'WX for a GLM; X'V⁻¹X at the fitted variance parameters for an LMM; for a GLMM, the fixed-effect information its standard errors come from, at the fitted variance parameters and the final PIRLS weights: the RX Schur complement under `wald_se="rx"` / `wald.se = "rx"` and after a `hessian_se_fallback`, the fixed-effect block of the joint Hessian otherwise) without pivoting, in the column order of the design, and for each column computes the share of its sum of squares that is left after the earlier columns are removed. The warning fires when the smallest share is below 1e-12, and names the column with that share. At this level an OLS or GLM coefficient has lost roughly three significant digits to rounding. The named column can be the intercept, one level of a factor, or an interaction term; its partners are not identified, and which member of the group is named depends on column order. The column stays in the model and its estimate is unbiased but imprecise. This differs from aliasing: an exactly redundant column is dropped and reported as NaN. The share is measured on glmm's internally standardized design (each column centered and scaled), so neither rescaling nor centering a column on its own removes the warning; centering a variable before it enters an interaction or polynomial term changes those columns and can. When the fit also carries `se_unavailable`, the two print as one warning: the `se_unavailable` text that names this column (below). |
| `hessian_se_fallback` | Caution | Simpler standard errors used | The usual standard errors could not be computed, so a simpler method was used. Its standard errors tend to be too small, so p-values and confidence intervals may look more precise than they are. Standard errors for the random-effect standard deviations are not available. | GLMM only, under the default `wald_se="hessian"` / `wald.se = "hessian"`. The default standard errors come from the joint Hessian of the Laplace deviance in the variance parameters and the fixed effects, computed exactly where the model shape allows it and by finite differences otherwise; this matches lme4's `glmer` default. The fallback fires when that Hessian is not positive definite, or when a finite-difference step gives a non-finite deviance. The standard errors reported instead come from the fixed-effect block alone (RX), which treats the variance parameters as known; this is what MixedModels.jl reports and what lme4 gives with `use.hessian = FALSE`, and for a GLMM it is anticonservative. The standard errors of the random-effect standard deviations need the joint Hessian, so they are NaN. Refitting with `wald_se="rx"` / `wald.se = "rx"` gives the same numbers without the failed attempt. |
| `se_unavailable` | Caution | Standard errors not computed | Standard errors could not be computed at the fit's end point: the fixed effects carry too little separate information. The estimates are usable; standard errors, p-values and confidence intervals are not reported. Check for predictors that are copies or near-copies of each other. | GLM and GLMM. On a GLMM: at the search's end point the information matrix of the fixed effects is not positive definite to rounding: the RX Schur complement fails, and under `wald_se="hessian"` / `wald.se = "hessian"` the joint Hessian failed before it. The estimates, the random-effect variances, the deviance and `converged` are the search's own; the standard errors, the covariance matrix and the random-effect standard-deviation standard errors are NaN. The usual cause is a predictor that is an exact or near copy of another; a fit through `fit`/`fastglmm` drops exact copies before fitting, so this is rare there. On a GLM (IRLS, including the inner fit of a negative binomial GLM) the fit converged, but at its last step the QR of √W·X has a zero or non-finite diagonal entry at a column that is not zero under the weights, so that column cannot be separated from the columns before it; the fit carries `ill_conditioned` for that column too, and prints the message in the next row. |
| `se_unavailable` | Caution | Standard errors not computed | Standard errors could not be computed: `<column>` cannot be separated from the other columns in the model. Its estimate is not reported. The other estimates and the deviance can be used; standard errors, p-values and confidence intervals are not reported. Check for predictors that are copies or near-copies of each other. | Printed in place of the message above when the fit carries `ill_conditioned` as well, which a GLM with `se_unavailable` always does: the column is the one `ill_conditioned` names, and `ill_conditioned` prints nothing of its own. On a GLM the fit held that column at its starting value, so its estimate is NaN; the other estimates, the deviance, the log-likelihood, the fitted values and `converged` are the fit's own; the standard errors and the covariance matrix are NaN. The model's df and AIC count only the estimated coefficients, so they match a fit with that column dropped. When several columns cannot be separated, only the first is named, and all of them are held and set to NaN. A fit through `fit`/`fastglmm` drops exact copies before fitting, so this is rare there. |
| `exact_profile_fallback` | Caution | Search retried with a different method | The default search method for this model did not settle on an answer, so the fit tried a different search method from the same starting point. The reported estimates come from whichever method reached the better answer. | GLMM only, on binomial, Poisson, negative-binomial and Gamma mixed models fitted with the default Laplace approximation (`nagq = 1` / `nAGQ = 1`), where the outer search profiles the fixed effects exactly at each candidate variance point (`ExactProfile`). Not raised on models with random slopes on two or more groupings, or too large for the dense layout, which take another route. When that search does not converge, the fit reruns once with a different outer-search strategy (`PqlThenJoint`: a warm-start pass on the approximate profile, then a joint search over variances and fixed effects together) from the same starting point. The reported estimates come from the rerun when it converges. When the rerun also does not converge, they come from whichever of the two attempts reached the lower deviance, and `converged` is still `False` / `FALSE`. |
| `gradient_search_fallback` | Caution | Search finished by another method | The fast search for this model did not settle on an answer, so the fit finished with the standard search from the best point it had reached. The reported estimates come from that search. | Linear mixed models whose random slopes are all on one grouping, with no other grouping, where every level's random-effect design has full rank (the per-group regression route), binomial, Poisson and Gamma GLMMs fitted by the Laplace approximation with at least two variance parameters, outside the packed layout, and logit and probit binomial and Poisson GLMMs with a random intercept only and fewer than 50 rows per group on average, fitted by adaptive quadrature (`nagq` / `nAGQ` above 1), except from a start value with a variance at or near zero. Those models search with a gradient method (BFGS); on a GLMM the note is raised only when that search fails, not where its gradient is undefined. When it stops without converging (a failed line search, an unavailable gradient, or its iteration cap), the derivative-free search every other model uses (BOBYQA) continues from the best point reached, with its own full evaluation budget, and the reported estimates and `converged` are that search's. When that search ends with no result (on a ridge the deviance with the coefficients re-solved can fail at every point it tries), the fit reports the point the gradient search reached, with `search_limit` in place of this note. `n_eval` counts both searches. |
| `precision_limited` | Caution | Numbers too large for full precision | The numbers in this fit are so large that rounding in the computer's arithmetic hides small changes in its deviance. The random-effect estimates, and the fixed effects that depend on them, may be off by a tenth of a standard error or more. This happens with counts in the billions or more, or when a model misses a large effect in such data; on a Gaussian model, with a response far from zero next to its residual spread (subtract a constant from it), or with weights spanning many orders of magnitude. | GLMM and Gaussian mixed models. On a Gaussian mixed model glmm estimates the rounding error of the deviance as (k + p + 1)·ε·y'Wy/σ̂², with k the random-effect columns, p the fixed ones and y'Wy the weighted sum of squares of the response: the residual sum of squares is a difference of numbers of that size. It passes 0.01 when the residuals are tiny against the response: a response far from zero next to its residual SD (about 1e5 times it at n = 1000, 1e4 at n = 20000), or weights spanning about 1e11 or more. The variance search then stops where it first meets that floor, so the log-likelihood can sit far below its maximum, and a fitted weight power (`weight_power = "estimate"`) can stop far from the best one. Under REML the estimate also counts each fixed-effect pivot of X'V⁻¹X, (k + p + 1)·ε·C_jj/L_jj², with C_jj the column's weighted sum of squares and L_jj² its pivot: the pivot is a difference of two large numbers when a fixed-effect column lies near the span of a random-effect column with a large variance, such as an intercept beside a random intercept. Measured with weights spanning 1e16 at a weight power of −2: the search stops at a random-intercept variance near 1e14, where the intercept's pivot is lost. On a GLMM, after the search, glmm estimates the rounding error of the reported Laplace deviance as ε·(\|D\| + t), with ε the double-precision machine epsilon (2.2e-16), D the deviance and t the trace of M'WM over the columns of the second and later grouping factors (M = ZΛ, W the final working weights; t is 0 with one grouping factor). The first term is the rounding of the deviance sum itself. The second bounds the rounding of log\|A\| (A = I + M'WM): with two or more grouping factors, A has an eigenvalue of exactly 1 next to eigenvalues of the size of those columns, and its factorization finds that one as a difference of much larger numbers. The note fires when the estimate is above 0.01 deviance units. A noise of δ in the deviance moves the variance estimates by about √δ of their standard error, so 0.01 is about a tenth of one, and the search sees several times the estimate. The deviance term reaches 0.01 at a deviance of about 4.5e13; on a 12-cluster Poisson model with a crossed 5-level factor, the crossed term reaches it at counts near e³⁰. `converged` and every estimate are the search's own. The inner PIRLS stop band is not the limit: PIRLS converges past it to the rounding floor. Fitting the missing effect removes the first source. |
| `agq_fallback` | Caution | Adaptive quadrature not used | nagq=`<k>` / nAGQ=`<k>` works only for binomial, Poisson, negative-binomial or Gamma models whose random effects are in one grouping factor, with at most 3 random effects in it. This model was fitted without adaptive quadrature. | Raised with the ignored-argument warnings, after `rows_dropped_na`. Adaptive Gauss-Hermite quadrature is available for binomial, Poisson, negative-binomial and Gamma GLMMs, with any link, that have one grouping factor and at most 3 random effects in it (the intercept plus slopes). The integral over each group uses k^q quadrature points, so the cost grows fast with q; q ≤ 3 is the range glmm has validated. A block without a random intercept, `(0 + x \| g)`, counts one more: the kernel keeps its intercept column at zero variance, so `(0 + x1 + x2 + x3 \| g)` is outside the range. Outside that range a mixed model is fitted with the Laplace approximation, and the fit records nagq = 1. A Gaussian model, or a model without random effects, has nothing to approximate; nagq there is reported as `argument_ignored`, not as this warning. The Laplace approximation can understate random-effect variances for binary or low-count data with few observations per group. |
| `non_integer_response` | Caution | Non-integer response | The response is not a whole number in `<rows>` row(s). This family expects integer counts (binomial: the number of successes, y * weights). The fit still ran, but check whether this is the right family for the data. | Poisson, negative-binomial and binomial GLM/GLMM fits. Raised when the response — for binomial, the derived successes `yᵢ·wᵢ` — is not within 1e-3 of an integer. | `rows_dropped_na` | Caution | Rows dropped for missing values | Dropped `<n>` of `<m>` row(s): a column the formula uses had a missing value there. Raised when a column the formula uses is missing a value on some rows and those rows are dropped before fitting. R does this through `na.action` (default `na.omit`); Python has no `model.frame` to do the filtering for free, so the port does the same row drop itself. | `satterthwaite_curvature` | Caution | Satterthwaite df uncertain | The Satterthwaite degrees of freedom are approximate: `<reasons>`. The t tests and confidence intervals use them as computed. When they could not be computed: The Satterthwaite degrees of freedom could not be computed: the fit has no finite end point, or the deviance near it was not finite. Every coefficient is tested with z, and its confidence interval uses the normal distribution. | Gaussian linear mixed models only. Their t tests use lmerTest's Satterthwaite degrees of freedom, built from a finite-difference Hessian of the deviance in the variance parameters at the fit's end point (central differences of the deviance, or of its analytic gradient on the models whose variance search uses it). `<reasons>` joins, with semicolons, the ones that apply: "the curvature of the deviance in the variance parameters has `<n>` flat direction(s), left out" (numerically zero eigenvalues of that Hessian, left out of its pseudo-inverse as lmerTest does), "it has `<n>` negative direction(s), so the fit may not be at a minimum" (not inverted), and "the variance search stopped at its step limit, so they are computed at its last point". ## The warnings of `predict`

`predict` raises two warnings of its own. They are not warnings of the fit: they are not stored in `m.warnings` / `m$warnings`, have no tier or title, and are not in the table above. The first is raised when `newdata` has a grouping level the fit did not see, one warning per grouping with such levels:

```
<n> row(s) of newdata has / have a level of <group> the fit did not see (rows <rows>). Their random effect for <group> is 0.
```

`<rows>` are the row numbers of `newdata`, counted from 0 in Python and
from 1 in R. Those rows are predicted with a random
effect of 0 for that grouping, and their other groupings keep theirs; on such
a row the standard error and the future bounds take nothing from that
grouping. In Python the warning class is `NewGroupingLevelsWarning`, a
subclass of `DiagnosticWarning`. In R the condition has the classes
`fastglmm_new_grouping_levels` and `fastglmm_diagnostic`. With
`allow_new_levels=False` / `allow.new.levels = FALSE` the same rows are an
error instead. In Rust it is `Note::NewGroupingLevels` in `Prediction::notes`,
and the error is `FitError::Ids`.

The second is raised when a row of `newdata` is not estimable from a rank-deficient fit (one with aliased columns):

```
Row <row> is not estimable from this rank-deficient fit, so its prediction is NaN.
Rows <rows> are not estimable from this rank-deficient fit, so their predictions are NaN.
```

`<rows>` are numbered as in the first warning, at most 10 of them, then ", and <n> more". A row `x` is not estimable when it lies outside the row space of the training design: `‖N·x‖ > 1e-6·‖x‖`, where `N` is an orthonormal basis of the null space of that design. This is the rule of R's `predict.lm`, which also warns here and gives `NA` with `rankdeficient = "NA"`. The prediction, standard error, interval and future bounds of such a row are NaN. Rows inside the row space, the training rows among them, use the kept coefficients. In Python the warning class is `RowsNotEstimableWarning`, a subclass of `DiagnosticWarning`. In R the condition has the classes `fastglmm_rows_not_estimable` and `fastglmm_diagnostic`. In Rust it is `Note::RowsNotEstimable` in `Prediction::notes`.

## The notes of a pairwise table

`pairwise` and its interval table (`confint` on a pairwise result) carry their notes as text under the table. When the fit did not converge, the first note of each table says so, and the two tables word it for what they show:

- Tests: The fit did not converge, so its estimates are not at a maximum and these tests are not reliable. Change the model until it converges (a simpler random part often helps), then test again.
- Intervals: The fit did not converge, so its estimates are not at a maximum and these intervals are not reliable. Change the model until it converges (a simpler random part often helps), then compute them again.

## Errors

An error stops the call: nothing is fitted and nothing is returned. Python raises the named exception; R raises a condition of class `fastglmm_error_<code>` for every error the shared layer behind both ports words, and a plain `stop()` condition for the checks that stay in one port (the tables for one port only, and the type checks of `anova` and `compare`). Text in `<angle brackets>` is filled in from the call. An argument keeps each language's own spelling (`nagq` / `nAGQ`, `None` / `NULL`, `True` / `TRUE`), and a row is numbered as each language numbers the caller's rows; everything else in the message is identical. A refusal of an option ends in the value given, for example `got the string "x"`, `got 2`, `got NA`.

A `<row>` in a message is a row of the data the call was given, counted
before any row was dropped (a missing value, R's `subset =`): from 0 in
Python, so "row 3" is `data.iloc[3]`, and from 1 in R, so "row 3" is
`data[3, ]`. For `predict()` with `newdata` it is a row of `newdata`.

### Error codes

Every error from the shared layer has a code. In Python it is the attribute `.code` of the exception; in R it is the end of the condition class, `fastglmm_error_<code>`, so `tryCatch(..., fastglmm_error_invalid_argument = function(e) ...)` works without matching message text.

| Code | Meaning | Python exception |
|---|---|---|
| `invalid_argument` | An argument is wrong: its form (`satterthwaite` is not a bool) or its value (`nagq` is even, `level` is outside (0, 1)). | `ValueError` |
| `fit_error` | The formula or the data cannot be lowered or fitted: a formula error, a response outside its family's support, no rows, a grouping level the fit did not see. | `ValueError` |
| `compare_error` | Two stored fits cannot be compared. | `ValueError` |
| `internal` | A bug in glmm: an unexpected panic, or a function that is not implemented yet. | `RuntimeError` |

A Python check that stays in the Python package (the type of an object passed to `anova`, `compare` or `pairwise`, the type of `data=` or `parm=`, and the arguments `anova` takes with one fit or with two) raises `TypeError` and has no `.code`.

### Argument and data errors

The options of `fit` are checked once, by the shared layer behind both ports, in this order: family, link, `inversegaussian` + random effects, `wald_se` / `wald.se`, `nagq` / `nAGQ`, `dispersion=`, `init_theta=` / `init.theta=`, `warm_start` / `start`, `satterthwaite`, `condvar`, `reml` / `REML`, `anova_test`, `weight_power`, `se_type`, and then the data. Each port first reads its data columns, `weights=` and `offset=`, and drops rows with a missing value. A Python `None` or an R `NA` given for an option gets that option's own refusal, for example `satterthwaite must be True or False, got None` and `REML must be NULL, TRUE or FALSE, got NA`.
