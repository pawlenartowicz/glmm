# speed campaign

## What this is

This is a benchmark grid for the `glmm` crate. It fits a grid of simulated
mixed models with three engines — `glmm` (Rust), `MixedModels.jl`, and
`lme4`/`GLMMadaptive` (R) — on the same data, and records wall time and
optimizer eval counts per cell. `manifest.json` defines 585 cells across
family, random-effect structure, and size. `estimate-grid-manifest.json` is a
second cell list fitted through the same `run.sh` and `fit.R`, pointed at its own
manifest and output tree through `GRID_MANIFEST`/`GRID_OUT`.

## Files

- `run.sh` — runs one engine over the grid, with a per-cell watchdog and resume.
- `fit.rs` — the glmm driver (cargo example `grid_fit`), one JSONL record per cell.
- `fit.jl` — the MixedModels.jl driver.
- `fit.R` — the lme4 / GLMMadaptive driver.
- `prep.R` — generates `manifest.json` and the per-cell CSVs in `data/`.
- `analyze.R` — reads engine JSONLs, writes the status map and summary CSVs in `reports/`.
- `common.R` — the readers and the beta agreement band `analyze.R` and `counters.R` share.
- `estimate-grid-manifest.json` — the second cell list (answer-agreement pass), read by
  `counters.R`'s AGQ join and fittable through `run.sh` with `GRID_MANIFEST`.
- `optima/` — best-known optima for the mismatch cells, frozen from `sweep_fit.jl`'s
  multi-start sweeps re-scored on glmm's objective.
- `report.R` — turns `reports/status_map.csv` into `reports/report.html`.
- `counters.R` — aggregates the optimizer counter fields from a counters pass.
- `sweep_fit.jl` — MixedModels.jl multi-start sweep for adjudicating β mismatches.
- `agq_par_probe.rs` — scratch timing probe for AGQ inner parallelism.
- `loop_bench.rs`: the loop-tier harness (cargo example `loop_bench`), see "loop_bench" below.
- `loop_summary.py`: summary and answer check for `loop_bench` output.
- `manifest.json` — the cell definitions (committed).
- `data/` — per-cell CSVs generated by `prep.R` (gitignored).
- `results/` — per-pass JSONL output and run metadata (gitignored).
- `reports/` — committed analysis output (CSVs, HTML report).

## Running a pass

```
./run.sh glmm|mixedmodels|lme4 <pass-tag> [budget-seconds]
```

`budget-seconds` defaults to 240 and is a **per-cell** budget, not per-fit and
not scaled by the number of fits in a cell.

- **glmm** treats the budget as soft: `fit_cell` (in `fit.rs`) decides after
  each fit whether the next one would fit inside the budget, and reports
  whatever finished. The bash watchdog's timeout is only a hang backstop
  (`budget + 60s`).
- **MixedModels.jl** and **lme4** have no usable partial result: MixedModels.jl's
  JIT warm-up means a partial run proves nothing, and lme4 does one fit with no
  warm-up at all. For these two, the watchdog's timeout **is** the budget, and
  it is the actual enforcement.

The watchdog polls the output file's modification time once a second. If it
goes stale past the effective timeout, `run.sh` kills the engine process,
writes a `status:"timeout"` stub record for the next unfinished cell, and
relaunches. A fresh launch that writes nothing yet gets a longer startup
grace (`GRID_STARTUP_GRACE`), since Julia's package load and JIT can outlast
one cell's budget; glmm skips the grace because it writes nothing until a
cell is fully done anyway.

Cells already present in the output JSONL are skipped, so re-running the
same `<pass-tag>` resumes an interrupted pass instead of refitting from
scratch.

glmm runs **one cell per process launch** (`GRID_ONE_CELL`, set by `run.sh`
only for the glmm engine). The wall of a cell under 100 ms depends on what the
process ran before it, by a factor of 2–10 when many cells run back to back. A
fresh process gives every cell the same timing context. Julia and R keep the whole grid in one process, since their
per-launch startup/JIT cost would dominate a per-cell budget.

Every engine is pinned to one CPU core with `taskset -c`, the core number
from `GRID_PIN_CORE` (default 1), when `taskset` is available. `run.sh` also
exports the BLAS, OpenMP, Julia and rayon thread counts as 1, so every engine
fits on one thread.

`run.sh` reads `/sys/devices/system/cpu/intel_pstate/no_turbo` and records it
into `run_meta_<engine>_<tag>.json`. It never writes to that file — locking
the clock is done outside this script — and prints a warning if the clock is
not locked.

The lme4 pass only fits the cells named in a file passed through `GRID_TODO`
(normally produced by `analyze.R`); `run.sh` aborts with an error if
`GRID_TODO` is unset for that engine.

## Environment variables

- `GRID_MANIFEST` — path to the manifest to run. Default: `manifest.json` next to `run.sh`.
- `GRID_OUT` — path of the output JSONL file. Default (from `run.sh`): `results/<engine>_<tag>.jsonl`; each fit script also has its own fallback path if run outside `run.sh`.
- `GRID_CONFIG_TAG` — the tag written into each record's `config_tag` field. Default: the pass tag (`run.sh` sets it), or empty string if a fit script is run standalone.
- `GRID_ONLY` — comma-separated `case_id` list to restrict the run to. Default: empty, meaning every cell in the manifest.
- `GRID_ONE_CELL` — glmm only. Any non-empty value makes the driver fit one cell and exit. `run.sh` sets this for the glmm engine only.
- `GRID_CELL_BUDGET` — per-cell time budget in seconds, read by `fit.rs` and `fit.jl`. Default: 240; `run.sh` always sets it from its own `[budget-seconds]` argument.
- `GRID_COUNTERS` — `run.sh` only. When set, glmm is built and run with the `validation/counters` cargo feature, adding stage/PIRLS/AGQ counter fields to each record.
- `GRID_PIN_CORE` — CPU core number passed to `taskset -c`. Default: 1.
- `GRID_STARTUP_GRACE` — seconds of no-output grace given to a fresh engine launch before the watchdog treats it as stuck. Default: `TIMEOUT + 180`.
- `GRID_TODO` — path to a file of `case_id`s, one per line, for the lme4 pass. Required for the lme4 engine; `fit.R` falls back to `GRID_ONLY` if `GRID_TODO` is empty.
- `GRID_TOLPWRSS` — `fit.R` only. Overrides `glmer`'s `tolPwrss` PIRLS tolerance. Default: `1e-13`.

## Pass tags and where results land

Each pass writes `results/<engine>_<tag>.jsonl` and
`results/run_meta_<engine>_<tag>.json` (engine, tag, timeout, `no_turbo`,
start time).

Fields `fit.rs` writes per record: `case_id`, `seed`, `engine`, `optimizer`,
`config_tag`, `n_reps`, `wall_source` (`"warmup"`, `"single"`, or
`"min_of_2"`), `n_eval`, `converged`, `singular`, `deviance`, `loglik`,
`dispersion`, `beta`, `se`, `varcomp`, `status`, `lower_seconds`,
`wall_seconds`, and an optional `rep_mismatch` flag when two timed fits of
the same cell disagree.

Under the `counters` feature (`GRID_COUNTERS`), each record also carries
`stage1_evals`, `stage2_evals`, `stage1_shrink_evals`, `stage2_shrink_evals`,
`pirls_hist`, `agq_evals`, `agq_node_evals`, `nb_nodes`, `nb_evals_total`.

A cell that times out or whose launch fails twice with no output gets a
smaller stub record written by `run.sh` itself: `case_id`, `seed`, `engine`,
`optimizer:""`, `config_tag`, `n_eval:0`, `converged:false`,
`singular:false`, `deviance:null`, `beta:[]`, `se:[]`,
`status:"timeout"`/`"engine-fail"`, `wall_seconds`.

## The manifest

Top-level keys: `schema`, `generated_by`, `b1_seed_suffixes`, `cells` (585
entries).

Each cell has: `case_id`, `family`, `structure`, `n_theta`, `n_obs`,
`per_group`, `balance`, `regime`, `seed`, `max_fun`, `b1`, `re_q`, `factors`,
`n_x`, `r_formula`, `jl_formula`, and `reml` (gaussian cells only); binomial
aggregated cells also carry `weights`.

Cell counts by family × `n_obs`:

| family | 300 | 3000 | 30000 |
|---|---|---|---|
| gaussian | 89 | 138 | 160 |
| binomial | 29 | 55 | 0 |
| poisson | 16 | 23 | 0 |
| negbin | 13 | 23 | 0 |
| gamma | 13 | 26 | 0 |

`prep.R` generates `manifest.json` and writes one CSV per cell into `data/`,
named `<case_id>.csv`. Cells flagged `b1` also get 5 seed-replicate CSVs,
`<case_id>_s1.csv` through `_s5.csv` (a different data seed each), matching
`b1_seed_suffixes`.

## Analysis

`analyze.R glmm.jsonl mixedmodels.jsonl [lme4.jsonl]` reads those JSONLs, the
tolerance definitions from `common.R`, and `manifest.json`. It writes
`reports/status_map.csv` (one row per cell: status, eval counts, aligned
deviances, wall times), `reports/eval_ratio.csv` (eval-ratio quantiles by
`n_theta` bin, family, structure, and regime), `reports/data_profiles.csv`
(a More-Wild style data profile), and `reports/lme4_todo.txt` (the case_id
list for the next lme4 pass: mismatch cells, cells where MixedModels.jl
failed but glmm didn't, and a fixed 20-cell random audit sample). It also
prints a status/eval-ratio summary to the console.

`report.R [status_map.csv] [out.html]` reads `reports/status_map.csv` by
default and writes `reports/report.html`, a per-structure table of glmm vs
MixedModels.jl wall time and eval count, colored by wall-time ratio.

`counters.R laplace.jsonl agq.jsonl out.csv [baseline.csv]` reads the
Laplace-pass and AGQ-pass JSONLs plus this manifest and
`estimate-grid-manifest.json`, and writes a joined counter table to
`out.csv`; the optional `baseline.csv` gets one row per family/structure
combination with median wall time and eval count from converged Laplace
cells.

## Other probes

- `sweep_fit.jl` — for the mismatch-adjudication multi-start sweep: fits each
  cell in `$SWEEP_STARTS` from a supplied θ₀ under a tightened optimizer
  schedule, gaussian REML cells only, and appends one JSONL line per
  (cell, start) to `$SWEEP_OUT`.
- `agq_par_probe.rs` — times `parallel_inner` off vs on at several `nagq`
  orders for every AGQ-eligible cell and prints the ratio; a one-off sanity
  check, not a campaign result, and nothing is written to disk.

## loop_bench

`loop_bench.rs` measures the loop tier, the build-once / fit-many path a power
simulation runs: `spec_sized_from_ids_pub` and `build_workspace` once per
shape, then `fit_on` on D simulated draws of that shape. It is not a gate and
asserts nothing about speed.

```
cargo build --release --example loop_bench --features "loop_advanced os_counters"           # timing runs
cargo build --release --example loop_bench --features "loop_advanced counters os_counters"  # count runs
RAYON_NUM_THREADS=1 target/release/examples/loop_bench --shape all --size both \
    --variant base --start all --draws 20 --warmup 3 --seed 46 --arm NAME --out run.jsonl
```

`os_counters` adds the per-fit thread CPU time, instructions and cycles
(macOS) and the block's `getrusage` CPU time and peak RSS, through three libc
calls, the only `unsafe` in this package. Without it the harness has no
`unsafe` and no direct libc dependency; the records carry wall time and those
fields are `null`. Speed work turns it on.

`--help` lists every option; `--list` prints each shape × size × variant with
its n, p, `n_theta`, level counts and the route the crate is expected to take.

**Data.** Generated inside the harness from fixed seeds, so the fit path stays
RNG-free: an inline xoshiro256** with Box–Muller normals, Knuth Poisson draws,
Marsaglia–Tsang gamma draws and gamma–Poisson negative-binomial draws (no RNG
crate, so the file builds against older versions of the crate). Each draw has
its own stream, seeded from (seed, shape, size, variant, draw index): a draw's
data never depend on the start mode, the warm-up length or what ran before it.
`raw-origin` uses the streams of `raw`, so the two draw the same data.
The group structure and the covariates are fixed per shape; each draw is a new
response generated from known β and θ. The `redraw` variant draws new
covariates as well.

**Shapes**, each at a `small` and a `large` size: `ols` (n 100 / 5000, p 5),
`glm_logit` (200 / 5000), `lmm_ri` and `lmm_slope` (200 rows in 20 clusters /
4000 in 100), `lmm_crossed` (subjects × items), `lmm_sparse` (subjects × items
with a random slope on both factors, which routes the sparse solver),
`glmm_logit_ri`, `glmm_probit_ri`, `glmm_pois_ri`, `glmm_logit_slope`,
`nb_ri`, `gamma_ri` (the joint search) and `agq_slope` (`nagq = 7` on a
random slope, vector AGQ), all 200 rows in 20 clusters / 2000 in 50;
`glmm_crossed` (logit, items declared before subjects, so the grouping reorder
runs) and `glmm_nested` (Poisson, parents × children).

**Variants.** `base`; `redraw` (new covariates per draw); `raw` (every mixed
shape: covariates on research scales nobody centers, age U(18, 70) per
subject, a 0/1 condition within subject, a score N(100, 15), unbalanced
cluster sizes, a slope on the uncentered score, and effect sizes on the
response's own scale: RT in ms on the Gaussian shapes, 25% prevalence on the
binary ones, mean 3 on the counts. The random-effect covariance holds at the
covariate means, where studies report it: each draw adds b₀ + b₁·(x − x̄) with
x̄ = 44 years, 0.5, 100 points); `raw-origin` (the slope shapes only: the same
data and normals as `raw`, with the same Σ values at covariate value 0, so at
the centre of the data the intercept SD is 3.8 times the stated one and the
intercept-slope correlation 0.97 on the logit shapes. A near-boundary stress
test, not typical data. Until 2026-10-02 this was the `raw` variant, so `raw`
records written before then are `raw-origin` records); `boundary` (the slope
shapes, with the slope SD shrunk 50-fold so that singular fits occur).

**Starts.** `cold` (no start), `truth` (β and θ of the generating model),
`carry` (the previous converged draw's `FitView::theta` and `betas`, starting
from the truth on the first measured draw) and `theta0` (MCPower's start when
it has neither a truth nor a carried start: θ = `[THETA0; n_θ]`, β the
generating β, MCPower's effect sizes). The default is `cold,truth,carry`;
`--start all` adds `theta0`. θ is in the crate's start
convention: per grouping in declaration order, the column-major vech of the
lower Cholesky factor of Σ, relative to σ on the LMM and absolute on the GLMM.
Σ is the covariance of the coefficients at covariate value 0, the origin of
the design the crate is handed: on `raw` that is N·Σ·Nᵀ, with N moving the
intercept row by −x̄ times each slope row.
The NB route exposes no θ̂ through the view, so its carry moves β only.

**The C arm** (`--prestandardized`): the harness standardizes each draw's
continuous columns by the crate's own rule and sets
`FitWorkspace::set_prestandardized(true)`. Starts are mapped onto the
standardized design, and β̂, θ̂, the RE covariance and the LMM's REML deviance
(`+ 2·Σ ln sⱼ`, REML is not invariant to rescaling X) are mapped back to raw
units, so its records compare with an ordinary arm's on the same seed.

**Records** (JSON Lines, appended to `--out`): one `header` per process (arm,
source, rustc, features, the probe's own median overhead, power source, Low
Power Mode, load average); one `block` per shape × size × variant × start
(family, n, p, `n_theta`, groupings, the generating β and θ, the expected
route, build time); one `draw` per fit; one `block_end` (summed fit wall and
CPU, the block's `getrusage` CPU, peak RSS). A `draw` record carries
`wall_ns` (`Instant` around the one `fit_on` call), `cpu_ns` (thread CPU
clock), `instr` and `cycles` (`proc_pid_rusage`, macOS), all three only with
`os_counters`, `n_eval`, `converged`, `boundary_hit`, `pinned_mask`, the other
loop-tier diagnostics,
`guard_evals_derived` (2 on every GLMM fit handed a θ start other than the
blind θ₀: the warm-start guard's two evaluations; when the search takes the
guard's winning solve over as its first evaluation, one of the two is also
counted in `n_eval`, otherwise both are outside it; 0 at the blind θ₀,
`THETA0` on each diagonal and 0 off it, where the guard is skipped),
`beta`, `theta`; with `--readout
full` (the default) also `deviance`, `loglik`, `objective` (the deviance, or
−2·loglik on OLS/GLM), `singular`, `boundary`, `dispersion`, `varcorr`, read
through `FitView::into_fit` after the timer stopped; and under `counters`
`stage_evals`, `shrink_evals`, `pirls_hist`, `pirls_iters`, `agq_evals`,
`agq_node_evals`, `nb_nodes`, `nb_evals_total` and the observed `route`.
Warm-up draws (`--warmup`, own stream) are recorded with `warmup: true`.

Every call into the crate sits in `loop_bench.rs`'s `mod api`; a build
against another version of the crate replaces that module only.

`loop_summary.py [--base ARM] [--starts] [--determinism] [--sanity] PATH...`
(Python 3, stdlib only) reads `loop_bench` JSONL files or directories of them
and prints, per arm and block, the median, IQR and minimum of wall and CPU time
per fit, CPU against wall, instructions, evals and PIRLS iterations per eval.
`--base ARM` is the answer check: every other arm against ARM on the same seed
and draw passes when the objective is within the grid's `dev_eps` (4e-5,
`grid/tol.R`; `dev_eps_agq_vec` 5e-4 on the vector-AGQ shape, whose deviance
moves by the quadrature difference under a change of standardization) and the
`converged` and `singular` flags agree. `--starts` runs the same check inside
each arm, truth and carry starts against the cold start of the same draw.
`--determinism` requires repeated records to carry bit-identical objectives and
equal eval counts. The exit status is 1 when a requested check fails.
