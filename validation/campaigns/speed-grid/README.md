# speed-grid campaign

## What this is

This is a benchmark grid for the `glmm` crate. It fits a grid of simulated
mixed models with three engines — `glmm` (Rust), `MixedModels.jl`, and
`lme4`/`GLMMadaptive` (R) — on the same data, and records wall time and
optimizer eval counts per cell. `manifest.json` defines 585 cells across
family, random-effect structure, and size. The sibling campaign
`../estimate-grid/` reuses this directory's `run.sh`, pointing it at its own
manifest and output tree through `GRID_MANIFEST`/`GRID_OUT`.

## Files

- `run.sh` — runs one engine over the grid, with a per-cell watchdog and resume.
- `fit.rs` — the glmm driver (cargo example `grid_fit`), one JSONL record per cell.
- `fit.jl` — the MixedModels.jl driver.
- `fit.R` — the lme4 / GLMMadaptive driver.
- `prep.R` — generates `manifest.json` and the per-cell CSVs in `data/`.
- `analyze.R` — reads engine JSONLs, writes the status map and summary CSVs in `reports/`.
- `report.R` — turns `reports/status_map.csv` into `reports/report.html`.
- `counters.R` — aggregates the optimizer counter fields from a counters pass.
- `sweep_fit.jl` — MixedModels.jl multi-start sweep for adjudicating β mismatches.
- `theta_eval.rs` — drives glmm's `loop_advanced` seam at fixed or custom θ.
- `agq_par_probe.rs` — scratch timing probe for AGQ inner parallelism.
- `manifest.json` — the cell definitions (committed).
- `data/` — per-cell CSVs generated by `prep.R` (gitignored).
- `results/` — per-pass JSONL output and run metadata (gitignored).
- `reports/` — committed analysis output (CSVs, HTML report).

## Running a pass

```
./run.sh glmm|mixedmodels|lme4 <pass-tag> [budget-seconds]
```

`budget-seconds` defaults to 240 and is a **per-cell** budget, not per-fit and
not scaled by the number of fits in a cell.

- **glmm** treats the budget as soft: `fit_cell` (in `fit.rs`) decides after
  each fit whether the next one would fit inside the budget, and reports
  whatever finished. The bash watchdog's timeout is only a hang backstop
  (`budget + 60s`).
- **MixedModels.jl** and **lme4** have no usable partial result: MixedModels.jl's
  JIT warm-up means a partial run proves nothing, and lme4 does one fit with no
  warm-up at all. For these two, the watchdog's timeout **is** the budget, and
  it is the actual enforcement.

The watchdog polls the output file's modification time once a second. If it
goes stale past the effective timeout, `run.sh` kills the engine process,
writes a `status:"timeout"` stub record for the next unfinished cell, and
relaunches. A fresh launch that writes nothing yet gets a longer startup
grace (`GRID_STARTUP_GRACE`), since Julia's package load and JIT can outlast
one cell's budget; glmm skips the grace because it writes nothing until a
cell is fully done anyway.

Cells already present in the output JSONL are skipped, so re-running the
same `<pass-tag>` resumes an interrupted pass instead of refitting from
scratch.

glmm runs **one cell per process launch** (`GRID_ONE_CELL`, set by `run.sh`
only for the glmm engine). The wall of a cell under 100 ms depends on what the
process ran before it, by a factor of 2–10 when many cells run back to back. A
fresh process gives every cell the same timing context. Julia and R keep the whole grid in one process, since their
per-launch startup/JIT cost would dominate a per-cell budget.

Every engine is pinned to one CPU core with `taskset -c`, the core number
from `GRID_PIN_CORE` (default 1), when `taskset` is available.

`run.sh` reads `/sys/devices/system/cpu/intel_pstate/no_turbo` and records it
into `run_meta_<engine>_<tag>.json`. It never writes to that file — locking
the clock is done outside this script — and prints a warning if the clock is
not locked.

The lme4 pass only fits the cells named in a file passed through `GRID_TODO`
(normally produced by `analyze.R`); `run.sh` aborts with an error if
`GRID_TODO` is unset for that engine.

## Environment variables

- `GRID_MANIFEST` — path to the manifest to run. Default: `manifest.json` next to `run.sh`.
- `GRID_OUT` — path of the output JSONL file. Default (from `run.sh`): `results/<engine>_<tag>.jsonl`; each fit script also has its own fallback path if run outside `run.sh`.
- `GRID_CONFIG_TAG` — the tag written into each record's `config_tag` field. Default: the pass tag (`run.sh` sets it), or empty string if a fit script is run standalone.
- `GRID_ONLY` — comma-separated `case_id` list to restrict the run to. Default: empty, meaning every cell in the manifest.
- `GRID_ONE_CELL` — glmm only. Any non-empty value makes the driver fit one cell and exit. `run.sh` sets this for the glmm engine only.
- `GRID_CELL_BUDGET` — per-cell time budget in seconds, read by `fit.rs` and `fit.jl`. Default: 240; `run.sh` always sets it from its own `[budget-seconds]` argument.
- `GRID_COUNTERS` — `run.sh` only. When set, glmm is built and run with the `validation/counters` cargo feature, adding stage/PIRLS/AGQ counter fields to each record.
- `GRID_PIN_CORE` — CPU core number passed to `taskset -c`. Default: 1.
- `GRID_STARTUP_GRACE` — seconds of no-output grace given to a fresh engine launch before the watchdog treats it as stuck. Default: `TIMEOUT + 180`.
- `GRID_TODO` — path to a file of `case_id`s, one per line, for the lme4 pass. Required for the lme4 engine; `fit.R` falls back to `GRID_ONLY` if `GRID_TODO` is empty.
- `LMM_NPT_FORMULA` — `fit.rs` only, and the one variable here without the `GRID_` prefix. Its value is written into `config_tag`. Default: `shipped`.
- `GRID_TOLPWRSS` — `fit.R` only. Overrides `glmer`'s `tolPwrss` PIRLS tolerance. Default: `1e-13`.

## Pass tags and where results land

Each pass writes `results/<engine>_<tag>.jsonl` and
`results/run_meta_<engine>_<tag>.json` (engine, tag, timeout, `no_turbo`,
start time).

Fields `fit.rs` writes per record: `case_id`, `seed`, `engine`, `optimizer`,
`config_tag`, `n_reps`, `wall_source` (`"warmup"`, `"single"`, or
`"min_of_2"`), `n_eval`, `converged`, `singular`, `deviance`, `loglik`,
`dispersion`, `beta`, `se`, `varcomp`, `status`, `lower_seconds`,
`wall_seconds`, and an optional `rep_mismatch` flag when two timed fits of
the same cell disagree.

Under the `counters` feature (`GRID_COUNTERS`), each record also carries
`stage1_evals`, `stage2_evals`, `stage1_shrink_evals`, `stage2_shrink_evals`,
`pirls_hist`, `agq_evals`, `agq_node_evals`, `nb_nodes`, `nb_evals_total`.

A cell that times out or whose launch fails twice with no output gets a
smaller stub record written by `run.sh` itself: `case_id`, `seed`, `engine`,
`optimizer:""`, `config_tag`, `n_eval:0`, `converged:false`,
`singular:false`, `deviance:null`, `beta:[]`, `se:[]`,
`status:"timeout"`/`"engine-fail"`, `wall_seconds`.

## The manifest

Top-level keys: `schema`, `generated_by`, `b1_seed_suffixes`, `cells` (585
entries).

Each cell has: `case_id`, `family`, `structure`, `n_theta`, `n_obs`,
`per_group`, `balance`, `regime`, `seed`, `max_fun`, `b1`, `re_q`, `factors`,
`n_x`, `r_formula`, `jl_formula`, and `reml` (gaussian cells only); binomial
aggregated cells also carry `weights`.

Cell counts by family × `n_obs`:

| family | 300 | 3000 | 30000 |
|---|---|---|---|
| gaussian | 89 | 138 | 160 |
| binomial | 29 | 55 | 0 |
| poisson | 16 | 23 | 0 |
| negbin | 13 | 23 | 0 |
| gamma | 13 | 26 | 0 |

`prep.R` generates `manifest.json` and writes one CSV per cell into `data/`,
named `<case_id>.csv`. Cells flagged `b1` also get 5 seed-replicate CSVs,
`<case_id>_s1.csv` through `_s5.csv` (a different data seed each), matching
`b1_seed_suffixes`.

## Analysis

`analyze.R glmm.jsonl mixedmodels.jsonl [lme4.jsonl]` reads those JSONLs, the
tolerance definitions from `../../tol.R`, and `manifest.json`. It writes
`reports/status_map.csv` (one row per cell: status, eval counts, aligned
deviances, wall times), `reports/eval_ratio.csv` (eval-ratio quantiles by
`n_theta` bin, family, structure, and regime), `reports/data_profiles.csv`
(a More-Wild style data profile), and `reports/lme4_todo.txt` (the case_id
list for the next lme4 pass: mismatch cells, cells where MixedModels.jl
failed but glmm didn't, and a fixed 20-cell random audit sample). It also
prints a status/eval-ratio summary to the console.

`report.R [status_map.csv] [out.html]` reads `reports/status_map.csv` by
default and writes `reports/report.html`, a per-structure table of glmm vs
MixedModels.jl wall time and eval count, colored by wall-time ratio.

`counters.R laplace.jsonl agq.jsonl out.csv [baseline.csv]` reads the
Laplace-pass and AGQ-pass JSONLs plus this manifest and
`../estimate-grid/manifest.json`, and writes a joined counter table to
`out.csv`; the optional `baseline.csv` gets one row per family/structure
combination with median wall time and eval count from converged Laplace
cells.

## Other probes

- `sweep_fit.jl` — for the mismatch-adjudication multi-start sweep: fits each
  cell in `$SWEEP_STARTS` from a supplied θ₀ under a tightened optimizer
  schedule, gaussian REML cells only, and appends one JSONL line per
  (cell, start) to `$SWEEP_OUT`.
- `theta_eval.rs` — reads eval/replay/sweep requests from `$THETA_EVAL_IN`
  and evaluates or fits them through glmm's `loop_advanced` seam, appending
  results to `$THETA_EVAL_OUT`.
- `agq_par_probe.rs` — times `parallel_inner` off vs on at several `nagq`
  orders for every AGQ-eligible cell and prints the ratio; a one-off sanity
  check, not a campaign result, and nothing is written to disk.
